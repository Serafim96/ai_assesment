# Как пользоваться mail-agent: сборка, настройка, подключение, запуск

Практическое руководство: что и куда поставить, что и где прописать, чтобы
пройти путь от «голого» кода до реально работающего цикла с настоящим Outlook
и настоящим LLM-ключом. Архитектурные объяснения — в [ARCHITECTURE.md](ARCHITECTURE.md),
тут только «сделай раз, два, три».

## 1. Что нужно физически иметь, чтобы это запустить

| Что | Зачем | Обязательно для |
|---|---|---|
| JDK 8 (не JRE) | компиляция и запуск | всегда |
| Maven 3.6+ | сборка | всегда (или используй локальный дистрибутив ниже) |
| Windows + установленный desktop Outlook с настроенным профилем | реальный почтовый канал | только для боевого режима (не для `--mock`) |
| Ключ API совместимого с OpenAI `chat/completions` эндпоинта | реальная LLM | только для боевого режима (не для `--mock`) |

Если Maven не установлен глобально в системе, можно использовать любой
локальный/портативный дистрибутив Maven — просто указывай полный путь к
`bin/mvn` вместо `mvn` в командах ниже.

## 2. Сборка

Из папки проекта:

```powershell
mvn clean package
```

Перед `package` автоматически прогоняется `mvn test` — он обязан быть зелёным
даже без Outlook/JACOB на машине (нативная зависимость исключена из
test-classpath, см. [ARCHITECTURE.md](ARCHITECTURE.md) §6). Результат сборки —
`target/mail-agent.jar` — один самодостаточный fat-jar со всеми зависимостями
внутри (`maven-shade-plugin`), запускать можно `java -jar` без дополнительного
classpath.

## 3. Быстрая проверка без Outlook и без LLM-ключа (демо-режим)

Это самый быстрый способ убедиться, что всё вообще работает, ничего заранее
настраивать не нужно:

```powershell
java -jar target/mail-agent.jar --mock --once
```

Что произойдёт: вместо реального Outlook и реального LLM подставляются
детерминированные заглушки (`MockMailChannel` с одним заранее зашитым письмом
«Какое сегодня число?», `MockLlmClient` с заранее прописанным диалогом:
модель вызывает `current_datetime`, затем отдаёт финальный текст). Пройдёт
ровно один цикл обработки (флаг `--once` — иначе процесс уходит в бесконечный
поллинг) и завершится. После запуска появится папка `data/` (или та, что
указана в `store.path` конфига) с файлами `seen.json`, `reminders.json`,
`audit.jsonl` — можно открыть `audit.jsonl` и увидеть JSON-строки событий
цикла (`agent_mail_seen` → `agent_tool_call` → `agent_reply_sent`), скреплённые
хэш-цепочкой.

Это же удобно как «smoke test» после любых изменений в коде: собрал →
`--mock --once` → посмотрел, что цикл прошёл без ошибок и без стектрейсов в
консоли.

## 4. Конфигурация — где что прописывается

Все настройки — в одном YAML-файле. Шаблон без секретов —
`config/config.example.yaml` (безопасно смотреть/коммитить). Для реального
запуска — **скопируй его в `config/config.local.yaml`** (это имя
исключено из git через `.gitignore` — секреты туда не утекут) и меняй уже
эту копию:

```powershell
copy config\config.example.yaml config\config.local.yaml
```

Приложение само подхватит `config.local.yaml`, если он существует рядом —
иначе откатится на `config.example.yaml`. Можно и явно указать путь флагом
`--config=путь\к\файлу.yaml`.

Поля конфига:

```yaml
llm:
  endpoint: "https://api.openai.com/v1/chat/completions"  # см. §5
  model: "gpt-4o-mini"                                     # имя модели у провайдера
  apiKeyEnv: "LLM_API_KEY"   # ИМЯ переменной окружения — не сам ключ!
  timeoutMs: 15000           # таймаут одного HTTP-запроса к LLM

agent:
  maxSteps: 6                # сколько раз подряд модель может вызвать инструмент
                              # на одно письмо, прежде чем цикл принудительно
                              # остановится с fallback-ответом (защита от зацикливания)

store:
  path: "./data"              # каталог для seen.json / reminders.json / audit.jsonl
                              # (создаётся автоматически, если его нет)

mail:
  pollSeconds: 30            # пауза между циклами опроса почты в бесконечном режиме
  profile: "Outlook"          # зарезервировано; текущая реализация OutlookMailChannel
                              # это поле не читает — всегда берёт профиль MAPI по
                              # умолчанию из Windows. Указывать можно, эффекта пока нет.
  folder: "Inbox"             # какую папку опрашивать: "Inbox" — папка входящих по
                              # умолчанию; любое другое значение ищется как
                              # подпапка внутри Inbox по имени
```

## 5. Как подключить настоящий LLM (не мок)

1. Нужен ключ API любого провайдера, чей HTTP-эндпоинт совместим с форматом
   OpenAI `chat/completions` (`tools`/`tool_calls` в запросе и ответе) — по
   умолчанию в примере указан сам OpenAI (`api.openai.com`), но подойдёт любой
   OpenAI-совместимый endpoint (включая локальные вроде LM Studio/Ollama в
   режиме совместимости, если он реализует именно этот формат tool-calling).
2. В `config.local.yaml` пропиши правильный `llm.endpoint` и `llm.model` под
   выбранного провайдера.
3. **Ключ никогда не пишется в конфиг** — только имя переменной окружения в
   поле `apiKeyEnv` (по умолчанию `LLM_API_KEY`). Сам ключ кладётся в
   переменную окружения перед запуском:

```powershell
$env:LLM_API_KEY = "sk-..."
java -jar target\mail-agent.jar
```

(В `cmd.exe`: `set LLM_API_KEY=sk-...`)

Если переменная не выставлена — приложение не упадёт с ошибкой при старте, но
`EnvSecretResolver` залогирует WARN, и запрос к LLM с пустым ключом закономерно
получит 401/403 от провайдера — это будет видно как `llm_failed` в логе и
аудите, письмо просто не будет обработано и попытка повторится на следующем
цикле (см. [ARCHITECTURE.md](ARCHITECTURE.md) §2.3 про идемпотентность и откат).

Без `--mock` LLM-клиент — `HttpLlmClient`: реальный HTTP через okhttp, с одним
ретраем при 5xx-ответе или сетевой ошибке.

## 6. Как подключить настоящий Outlook (не мок)

Требования:
- Windows (не работает на Linux/Mac — используется нативный COM-мост JACOB).
- Установленный **desktop**-клиент Microsoft Outlook (не веб-версия OWA, не
  «Новый Outlook» на UWP/электроне — только классический Win32 COM-Outlook).
- Профиль Outlook уже настроен и хотя бы раз открыт интерактивно (COM
  подключается к уже сконфигурированному MAPI-профилю, сам его не создаёт).
- Outlook либо уже запущен, либо будет запущен автоматически при первом
  обращении `ActiveXComponent("Outlook.Application")` — в среде без
  интерактивной сессии (например, сервис/задача планировщика без залогиненного
  пользователя) COM-автоматизация Outlook, как правило, не работает — это
  ограничение самого Outlook, не этого кода.

Запуск без `--mock` автоматически означает боевой `OutlookMailChannel` вместо
`MockMailChannel` (переключение — по факту наличия/отсутствия флага
`--mock`, отдельного флага именно на почтовый канал нет):

```powershell
java -jar target\mail-agent.jar
```

Что произойдёт при опросе: приложение получает MAPI-namespace, берёт папку по
`mail.folder` из конфига (по умолчанию — Inbox), фильтрует в ней письма с
`Unread=true`, для каждого забирает `EntryID`/`SenderEmailAddress`/`Subject`/
`Body`/`ReceivedTime`. При ответе — ищет письмо в той же папке заново по
`EntryID`, вызывает `Reply()`/`Send()` через COM (то есть письмо реально
уйдёт из настоящего почтового ящика — это не dry-run в боевом режиме).

**Важно и не проверено на машине разработки:** класс `OutlookMailChannel`
писался строго по контракту и документации JACOB, но живой прогон против
реального Outlook на этой машине не проводился (нет тестового ящика). Первый
реальный запуск на твоей/экзаменационной машине стоит делать на тестовом
ящике с парой безобидных писем, а не сразу на боевой почте — на случай если
всплывёт версия Outlook/локаль, на которую контракт не рассчитан.

Любая COM-ошибка (`ComFailException`) не обрушивает процесс — она
перехватывается, оборачивается в `MailChannelException`, логируется как WARN
(`mail_channel_error`), и текущий цикл поллинга просто пропускается — на
следующем цикле (`pollSeconds` спустя) попытка повторяется.

## 7. Режимы запуска — сводная таблица флагов

| Флаг | Что делает | Комбинируется с |
|---|---|---|
| (без флагов) | боевой Outlook + боевой LLM, бесконечный поллинг каждые `pollSeconds` | — |
| `--mock` | подменяет и почту, и LLM на детерминированные заглушки | обычно вместе с `--once` для демо |
| `--once` | одна итерация `processCycle()` вместо `while(true)` | можно и с боевыми каналами — один прогон и выход |
| `--config=путь` | явный путь к YAML вместо авто-поиска `config.local.yaml`/`config.example.yaml` | с любыми |

Обрати внимание: `--mock` переключает **оба** канала разом (и почту, и LLM) —
частичного мока (например, реальный Outlook + мок-LLM) флагами не
предусмотрено. Если это понадобится для отладки — придётся временно
подправить `App.buildMailChannel`/`buildLlmClient` руками.

## 8. Как понять, что процесс реально что-то делает (логи и аудит)

Два разных места, не путать:

- **Технический лог** (`logback`, идёт в консоль/файл в зависимости от
  `logback.xml`) — обычные структурные строки уровня INFO/WARN/ERROR, без
  тела/темы писем. Смотри на них при отладке — "почему письмо не ответило".
- **Аудит-журнал** — файл `audit.jsonl` внутри `store.path` (по умолчанию
  `./data/audit.jsonl`). Каждая строка — отдельный JSON-объект с полями
  `seq`, `eventKey`, `detailsJson`, `prevHash`, `hash`. Ключи событий:
  `agent_mail_seen`, `agent_tool_call`, `agent_reply_sent`, `llm_failed`,
  `mail_channel_error`, `agent_maxsteps_exceeded`. Это протокол «что вообще
  произошло за всё время работы», переживает рестарты (файл не перезаписывается,
  только дописывается). Целостность можно программно проверить методом
  `AuditLog.verify()` — если кто-то отредактировал файл руками задним числом,
  `verify()` вернёт `false`.

## 9. Данные, которые накапливаются на диске

Всё внутри каталога `store.path` (по умолчанию `./data`, создаётся
автоматически при первом запуске):

| Файл | Что содержит | Что будет, если удалить вручную |
|---|---|---|
| `seen.json` | id уже обработанных писем | приложение при следующем запуске посчитает все эти письма новыми и обработает повторно (если они всё ещё непрочитаны в Outlook) |
| `reminders.json` | напоминания, добавленные через инструмент `add_reminder` | инструмент `find_items` перестанет находить старые записи — они физически исчезнут |
| `audit.jsonl` | append-only журнал событий с хэш-цепочкой | пропадёт история аудита; новый файл начнёт цепочку заново с genesis-хэша |

Все три файла пишутся атомарно (запись во временный файл + `Files.move` с
`ATOMIC_MOVE`) — обрыв процесса ровно посреди записи не может оставить файл в
битом полусостоянии.

## 10. Типичные проблемы при первом запуске

- **`ConfigException: Missing required config field ...`** — в
  `config.local.yaml` не заполнено обязательное поле (см. §4 — все поля из
  примера обязательны, `ConfigLoader` явно это проверяет при старте, до
  начала работы).
- **LLM отвечает 401/403** — не выставлена или неверна переменная окружения
  из `apiKeyEnv` (по умолчанию `LLM_API_KEY`) — см. §5.
- **Ничего не происходит в реальном режиме, никаких новых событий в
  `audit.jsonl`** — вероятно, в Inbox просто нет непрочитанных писем
  (`Unread=true` — единственный критерий выборки), либо `mail.folder` в
  конфиге указывает не туда, куда реально приходят письма.
- **Процесс в боевом режиме "висит" и ничего не берёт из Outlook** — Outlook
  COM-автоматизация штатно не работает без интерактивной пользовательской
  сессии (например, из-под службы Windows/задачи планировщика без
  залогиненного пользователя) — запускай интерактивно, в сессии, где Outlook
  реально можно открыть на экране.
